Architecture — Medallion (validated)

Mirrors the repo's docs & SQL. All layer descriptions quote README.md & sql/gold/*.sql.

LAYER 1 — BRONZE

🗄️ bb_bronze — Raw landing

Every CSV loaded exactly as received. All columns TEXT. No cleaning. Preserves replay lineage.

  • 8 tables mirroring 8 real CSVs (see row counts above)
  • Python Pandas ingestion — bronze_mysql_load.py
  • Audit: _bronze_loaded_at DATETIME
LAYER 2 — SILVER

🧹 ss_silver — Clean & conformed

Typed, trimmed, deduped. 1 row / business key via window functions.

  • CAST to DATE / DECIMAL / INT / BOOLEAN
  • ROW_NUMBER() OVER (PARTITION BY pk ORDER BY load_time DESC)
  • Business rule: status IN ('completed','refunded') = valid
LAYER 3 — GOLD

📊 gg_gold — BI-ready (6 tables)

Pre-aggregated, denormalized, indexed. Plug into Power BI. Ref date = MAX(txn_date) = 2024-12-31.

  • customer_360, product_performance, sales_monthly_summary, sales_by_category_channel, marketing_performance, inventory_status
  • Indexed on (year_month, category, channel), customer_status, stock_status

Tech Stack & How Gold is Computed (real SQL)

🐬 MySQL 8.0 window funcs 🐍 Python Pandas ingest 📊 Power BI pbix reads gg_gold 🗂️ 8 CSVs • 100k txns ⭐ 6 Gold tables • indexed
  • Valid sales = status IN ('completed','refunded'); cancelled (5,049) excluded — matches gg_gold_load.sql line 20.
  • @ref_date = MAX(date) = 2024-12-31 — swap to CURDATE() for live feed.
  • Customer status: diff ≤90 Active, ≤180 At Risk, else Churned; no valid orders → No Orders (32 customers).
  • 90-day velocity: SUM(quantity)/90 where date > @ref_date -90d → days_of_supply.
