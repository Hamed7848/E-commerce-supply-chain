03 · Methodology

The rules & the ways of data analysis

These are the exact business rules applied in the Gold layer. They define what every number on this page means, so the analysis stays consistent, auditable and reproducible.

1

"Valid" sales filters the fact table

Only completed and refunded transactions count as real sales. Cancelled orders are kept for visibility but excluded from revenue, profit and units.

status IN ('completed','refunded') -- = valid
src: gg_gold_load.sql · used in all 6 Gold tables
2

Reference date for "recent" windows

Churn and 90-day velocity windows are measured from @ref_date = MAX(txn_date). For a live feed this becomes CURDATE(); here it is 2024-12-31 because the dataset is historical.

SET @ref_date := (SELECT MAX(txn_date) FROM ss_silver.silver_transactions);
src: gg_gold_load.sql line 23
3

Customer segmentation (churn)

Each customer maps to one status from their last order date vs @ref_date:

0 orders -> 'No Orders' diff <= 90 days -> 'Active' diff <= 180 days -> 'At Risk' else -> 'Churned'
src: gold_customer_360 · DATEDIFF(@ref_date, last_order_date)
4

Stock status

Replenishment urgency from current stock vs the product's reorder point:

stock = 0 -> 'Stockout' stock <= reorder -> 'Below Reorder Point' stock > reorder -> 'Healthy'
src: gold_product_performance & gold_inventory_status
5

Days of supply (90-day velocity)

How long current stock lasts given recent demand — the reorder trigger: days_of_supply = stock ÷ avg daily units sold over the last 90 days.

avg_daily_90d = SUM(quantity) / 90 WHERE txn_date > DATE_SUB(@ref_date, INTERVAL 90 DAY)
src: gold_inventory_status · valid statuses only
6

Reporting reconciliation (marketing)

Ad platforms report revenue; the sales ledger shows what actually happened. Gold joins both on month + channel and exposes the variance — the honest way to audit ROAS.

variance_pct = 100 * (actual_rev - reported_rev) / reported_rev
src: gold_marketing_performance · JOIN transactions ON month+channel
7

Return rate

Returns are measured per customer and per product, always against the valid order/unit base — never against total rows (which would include cancelled).

return_rate_pct = 100 * total_returns / valid_units
src: gold_customer_360 / gold_product_performance
8

Profitability & average order value

Derived, not measured: margin = profit ÷ revenue, and AOV = revenue ÷ completed orders (refunded revenue still counts; the order count base is 'completed').

AOV = SUM(revenue) / SUM(status='completed') margin = 100 * profit / revenue
src: gold_sales_monthly_summary & gold_product_performance

Deeper methods: Silver de-duplicates with ROW_NUMBER() OVER (PARTITION BY … ORDER BY bronze_id DESC) (keeps the most recently ingested row), trims & NULLs every text column, and runs under STRICT_TRANS_TABLES — see sql/silver/ss_silver_load.sql.

05 · Findings

What the data says

Insight highlights derived from the real aggregates above — each one traceable to a Gold table.

Key insight highlights

  • Electronics drives revenue, not margin. 46.1% of revenue ($23.2M) but only ~20.6% gross margin — vs Clothing at 16.7% of revenue and ~52.4% margin. Category mix decides company margin.
  • Marketing platforms systematically over-report. Sales-ledger truth is 3.9–7.2% lower than ad-platform revenue in every channel of 2024-12 (organic_search −4.76%, direct −7.17%). Spend decisions should use actuals.
  • Return rate 7.5% overall — 7,126 returns, $3.71M refunded. It is uniform, not concentrated: product-level return rates cluster at 2–4%.
  • 60 of 500 SKUs sit below reorder point, 0 are stocked out. The 90-day velocity rule makes the next reorder date calculable per product (e.g. PROD0216: stock 7 / reorder 11 → ~14 days of supply).
  • Customer base skews active (58.3%) but 24.8% churned and 16.5% at risk within 180 days — retention is the cheapest growth lever.
  • Strong holiday seasonality. Nov–Dec revenue runs ~40–60% above the yearly average while AOV dips — discount-driven volume spikes (promo months = 14.5% of price_history rows).
